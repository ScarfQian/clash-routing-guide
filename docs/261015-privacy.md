# 公开项目与本地秘密分开

日期：2026-10-15；创建人：项目维护者。

## 可以公开

设计原理、经过重新编写的通用代码、公开服务域名、DNS 服务地址、文档保留 IP、虚构节点、通用测试，以及只包含这些文件的发布目录。

## 必须留在本地

订阅链接及 token、节点 server/IP/端口组合、用户名和密码、UUID、Reality 参数、认证 JSON、API 密钥、控制器 secret、真实节点名称、账户邮箱、用户目录、连接日志、HAR、抓包、出口检测截图，以及含这些内容的备份或生成配置。

Reality 公钥未必是密码，但与节点和其他参数组合后会暴露真实连接信息，因此不放入本项目。不要把密码替换掉后就认为完整订阅可以公开。

`local/` 和 `backups/` 只是方便分开保管，不是加密保险箱；仍由自己的设备权限和备份策略保护。

## 发布流程

```sh
npm run check
npm run release
```

工具先核对 `PUBLIC_FILES.json`，检查公开文件中的邮箱、个人目录、UUID、疑似凭据、认证链接和非示例公网 IPv4，再复制清单内容到 `dist/clash-routing-guide-public/`。本地资料与备份不会被带入。

检查器是有限规则检测，不是「绝不泄漏」认证。IPv6、身份描述、供应商域名、自定义截图、注释和混淆凭据仍需人工审阅。以后添加功能或新文件时，同步审阅清单；不要为了通过检查而盲目扩充允许列表。

上传前只打开发布目录，逐个确认没有私人材料，再将其内容上传到自己选定的 GitHub 仓库。`.gitignore` 只影响部分 Git 操作，不能阻止网页拖拽私有文件。

本地工具不会执行 Git、创建仓库、推送、发消息、读取客户端数据目录或上传遥测。发布、许可证选择和第三方代码引入由项目拥有者另行决定；当前未指定开源许可证，不应推断已授予开源许可。

## 公开问题反馈怎么写

提供客户端/内核版本、操作系统、脱敏后的结构示例、发生阶段、错误类别和复现步骤。节点命名为 Example-A/Example-B，地址换成文档保留地址，秘密替换为 REPLACE_ME。

不要直接粘贴整份运行配置。不要上传含真实域名、账号或出口地址的截图。首次反馈可只写结构，维护者确需更多证据时再约定最小范围与脱敏方式。
